# ZOLA — RAW KNOWLEDGE BASE (handoff for another AI agent)

Purpose: transfer EVERYTHING factual about the Project Zola system and its
hardware to another AI agent, with zero aesthetic description. Every number
below comes from the code, the physics profile, the print manifest, or a
verified test. Where a value is assumed, it is marked.

One geometric correction up front: the four fans are mounted on the
**reinforced collar at the base of the neck** (two per side), not on the
head itself. The head carries only the single sensor lens. Everything else
below is as-built.

---

## 1. IDENTITY (one paragraph)

Zola is a sovereign, offline-first AI pet implemented as an aerial/bipedal
hybrid: a walking, gesturing humanoid chassis with four ducted fan
thrusters on a neck collar for hovering flight. Two computers run her:
a **Raspberry Pi 5** (the "brain": local LLM via Ollama, the operator
panel, 12 trained RL skills as ONNX) and an **ESP32-S3 flight controller**
(the "body": FreeRTOS dual-core flight firmware). They talk over a serial
UART and a Wi-Fi UDP lane using fixed binary packet formats. She is
air-gapped: her only external service is a local Ollama server.

## 3. THE JOINT SYSTEM

- **41 actuated joints total** in the physics profile.
- **34 are in the RL action space**: 22 arm/hand joints (shoulders,
  elbows, wrists, 5 finger-flex per hand) + 12 leg joints.
- The rest: neck, waist, and the 4 frozen collar-thruster mounts
  (±0.001 rad — "frozen" joints, because fixed joints weld away in PhysX).
- Actuation: position-controlled PD servos (the effort-write path in this
  Isaac build is broken; the torque-mode code exists, cfg-gated, unused).
- Named pose library (env_cfg.py): FLIGHT_POSE, SIT_POSE (knee 0.55 — the
  only depth the physics allows; knee 1.0 is statically unholdable),
  HERO_POSE (knee 0.45), PICTURE_POSE, THUMBS_UP_POSE, plus two
  choreography routines (the halobeat dance, the talking routine).

## 4. PROPULSION

- **4 × ducted fan thrusters**, mounted on a reinforced collar at the base
  of the neck — 2 per side, on articulated mounting arms. In the physics
  they are REAL BODIES (`collar_*_thruster`), each receiving force at its
  own center of mass. (The build's wrench composer only honors
  force-at-CoM in the body frame — this is why the rotors are bodies.)
- Quad layout: ±0.10 m pitch arm (dx), ±0.05 m roll arm (dy) — the
  rectangular-X mixer: `δF_i = τ_x·y_i/(4dy²) + τ_y·x_i/(4dx²)`.
- Motors: 4 × brushless ESCs, **DShot600 digital protocol** via the
  ESP32-S3's RMT peripheral (600 kbit/s, 16-bit frame: 11-bit throttle +
  telemetry bit + 4-bit CRC; MSB-first; bit period 1667 ns; ratio-encoded:
  '1' ≈ 75 % high, '0' ≈ 37.5 % high).
- Motor GPIOs: FL 5, FR 18, RR 19, RL 15.
- Flight modes: STABILIZED (cascade PID + QuadX mixer), AUTONOMOUS_MESH
  (waypoints; steering is bench-phase), FAILSAFE_LAND (a 3-second
  controlled descent ramp), DISARMED (boot state; motors idle).
- Throttle domain: mixer outputs 1000–2000 µs → DShot 48–2047.
  0 = DISARM command (preserved); 1–47 = the reserved command band (clamped).

## 5. FLIGHT CONTROL (ESP32-S3)

- **MCU**: ESP32-S3, dual-core 240 MHz. Alternative: STM32F405.
- **RTOS**: FreeRTOS, pinned: flight control @ **500 Hz on core 1**
  (high priority), telemetry/communications @ **100 Hz on core 0**.
  State crosses cores through a spinlock-guarded snapshot.
- **Attitude**: Madgwick gradient-descent AHRS (6-axis, β = 0.1) — the
  EXACT gradient s = Jᵀf (NOT the widely-copied vendored snippet, whose
  equilibrium provably settles a true 20° tilt at 63.18°). Gyro enters in
  RADIANS/s (a degrees/s hand-off was caught by the math mirror).
- **Control law**: the cascade — angle loop (8°/s per °) → rate PID
  (Kp 1.2 / Ki 0.05 / Kd 0.03 roll+pitch; 2.5/0.1/0.0 yaw; integral
  clamped ±200; derivative on error) → the QuadX mixer matrix
  (M1 +R+P−Y · M2 −R+P+Y · M3 −R−P−Y · M4 +R−P+Y — row sums zero).
- **Boot state: DISARMED.** Arming requires: a command payload byte 0xA5
  (the interlock), a live IMU, a fresh gyro bias, level within ±3.5°,
  battery ≥ 11.1 V.
- **Failsafe**: no valid command for 500 ms while armed → a 3 s controlled
  descent → DISARMED. In AUTONOMOUS_MESH, mesh death > 2 s → Return-To-Home.
- Source: `firmware/zola_fc/zola_engine.cpp` (+ 8 satellite modules),
  built with PlatformIO, `partitions_zola.csv` (dual OTA banks + an 8 MB
  `zolalog` data partition). **Compiles clean and links** (verified).

## 7. THE PACKET CANONS (binary, little-endian — memorize these)

**TELEMETRY (36 bytes, 100 Hz, FC → ground):**
`FA FB` · seq u32 · ts µs u32 · roll/pitch/yaw f32 (DEG) · m1–m4 u16 (µs,
1000–2000) · battery_mv u16 · CRC16 (bytes 0–31; reflected poly 0xA001,
init 0xFFFF) · footer `FC FD`.
CRC routine (both ends, byte-exact): `crc ^= b; ×8: crc = (crc&1) ?
(crc>>1)^0xA001 : crc>>1`.

**PDB VARIANT (36 bytes, 2 Hz):** header `FB FC` · seq · current_mA ·
power (cW) · mAh · esc_temp_max_c · sag_mv · throttle_limit_pct ·
eRPM/100 ×4 · v_bus_mv · flags · **state annex bytes 27–33** (mode,
sensor flags, wp_index, wp_count, leader_id, live_peers, braking) · CRC
(bytes 0–33).

**COMMAND (16 bytes, ground → FC):** header `CA FE` · cmd_id u8 · payload
9 B · CRC16 (bytes 0–11) · footer `EF AC`. Commands: 0x00 HEARTBEAT
(the failsafe's pulse — ≥ 2 Hz or she descends), 0x01 ARM (payload[0]
MUST be 0xA5), 0x02 EMERGENCY DISARM (no token — killing is easy),
0x03 SET_WAYPOINT (x_cm, y_cm, z_cm, yaw_cdeg, flags), 0x04 UPDATE_PID
(axis mask + kp + ki), 0x05 DUMP_BLACKBOX (refused while armed).

**ACK (14 bytes, FC → ground):** `4F 4B` ("OK") · cmd_id · result
(0 OK / 1 REJECTED / 2 UNKNOWN / 3 REFUSED) · timestamp u32 · mode u8 ·
pad · CRC (bytes 0–9) · `21 21`.

**OTA frames:** `0F 0D` · phase (0 START / 1 DATA / 2 COMMIT / 3 ABORT) ·
seq u16 · total u32 · offset u32 · len u16 · payload · CRC over the
prefix+payload. Commit payload = the 32-byte SHA-256 + the signature
(ED25519 64 B, or HMAC-SHA256 32 B with the device key — the guaranteed
floor). Dual-bank (ota_0/ota_1); a 10-second boot health gate rolls back
a bank that fails its sensor handshake.

**SWARM (ESP-NOW state vector, 26 bytes, 50 Hz, AES-128 per-peer):**
node_id · leader_id · wp_index · flags · x/y/z f32 · yaw f32 ·
battery_mv u16 · seq u32. Leader = the LOWEST LIVE node id (deterministic;
200 ms peer timeout). OTA chunks relay through the leader (a 2-byte tag
0F DA prefixes relayed chunks; ≤ 200 B each).

**BLACKBOX:** 8 MB ring of 37-byte records (1 type + 36 payload):
type 0x01 = a telemetry frame verbatim; 0x02 = an EVENT (id + ms +
detail): mode changes, failsafe, waypoint arrivals, calibration, thermal
brake. Dump command streams offset-addressed CRC'd chunks (`FD 0D`).

## 9. THE BRIDGES (ground side, Python)

- `bridge/zola_bridge.py` — the USB-serial bridge: ONE reader → N
  WebSocket clients (:8002), CRC-verified, byte-exact resync; forwards
  panel commands; DEMUXES the blackbox dump chunks into Saved/blackbox/;
  `--sim` mode generates spec-shaped frames (no FC needed).
- `bridge/zola_udp_bridge.py` — the Wi-Fi lane: UDP 8888 → WS :8003;
  same decode canon; commands fly back to the FC's source address;
  `--sim` spawns a fake FC that also listens for commands.
- `bridge/zola_pathfind.py` — NetworkX 3.6.1 A* over the FC's costmap
  (no-corner-cutting; a built-in A* fallback).
- `Scripts/zota_ota_tool.py` — signs (ED25519, `cryptography`), verifies,
  deploys (BEGIN → CHUNKs → COMMIT over the bridge WS).
- `Scripts/blackbox_fft.py` — numpy FFT on the dumped log → resonance
  peaks → notch proposals. NYQUIST: the 100 Hz log caps the band at 50 Hz.
- `Scripts/hil-test.mjs` / `hil-udp-test.mjs` — end-to-end proofs of both
  lanes (100 fps, monotonic sequences, the disarm round trip).
- `Scripts/firmware_math_check.py` — **122 assertions** mirroring the
  firmware's pure math (Madgwick convergence, DShot CRC4, the cascade,
  the mixer, every packet canon, Haversine, the fusion, the elections).
  Run BEFORE flashing. It has caught 3 real bugs (the rad/s hand-off,
  the vendored Madgwick's wrong equilibrium, the OTA layout mismatch).
